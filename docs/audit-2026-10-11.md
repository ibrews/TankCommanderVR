# Tank Commander VR audit — 2026-10-11

The largest immediate gains are reliable physical controls and a cockpit that stays
within seated reach. This pass fixes those problems, improves readable guidance,
and reduces unnecessary rendering work while preserving procedural art and
the Godot Mobile/OpenXR architecture.

## Findings and changes

| Priority | Finding | Result |
|---|---|---|
| P0 | Quest Touch Plus had no explicit action-map profile. Under Meta XR Simulator 207, Operator poses were active while the game's poses/actions stayed inactive. | Add Godot 4.7's canonical Touch Plus profile while retaining Touch, Pico and hand profiles. Real controller input now reaches the game. |
| P0 | Hand mesh poses/pinch strengths could override live controllers; a synthetic hand-interaction controller was indistinguishable from a physical controller. | Select input using the active profile, prefer controller poses during controller play, gate pinch input by tracking, and show one hand representation. |
| P0 | Switches repeatedly toggled while touched; buttons could stay held after leaving the coarse poke range. | Trigger switches on touch entry, send leave/reset updates, select one nearby poke target per hand, aggregate both hands, and require withdrawal after enabling guarded switches. |
| P0 | Grips lacked release hysteresis, allowed another hand to steal controls, and survived pause/tracking loss. | Acquire above 55%, retain above 40%, release safely, and restrict discovery to unowned controls in the current vehicle. |
| P0 | Grabbing could race empty-hand firing; turret-trigger firing also applied forward throttle. | Give physical controls priority over fallback actions; firing the held turret stick no longer supplies throttle. |
| P1 | Tillers were low/forward, IR activation was on the far wall, the horn was near the floor, and the reload lever moved away during driver-seat turret traverse. | Bring driving controls closer, put IR activation on the pedestal, raise the horn, and keep the reload lever with the crew basket. |
| P1 | Wheel discovery tested only its top point. Grab initialization used a different pose from movement. | Test distance to the full rim and use the same effective hand position throughout. Preserve lever value on initial grab. |
| P1 | Radio knobs never consumed wrist orientation. | Support wrist-twist rotation, with arc dragging retained as a fallback. |
| P1 | Long prompts were hard to scan; the next control lacked coaching; reload advice was overwritten. | Use shorter two-line prompts, larger hint text, outlined labels, blue coaching, amber proximity feedback, and persistent reload advice. |
| P1 | Thermal sight rendered at headset frame rate; hidden debug text was rebuilt every tick; unsupported FSR1 was configured on Mobile. | Schedule thermal renders at 30Hz while enabled, skip hidden diagnostic text, and use supported bilinear scaling at unchanged 1.0 scale. |
| P1 | Build wrapper wrote to the canonical checkout and killed every Godot process/Gradle daemon. | Use a named worktree, preserve artifacts, route caches/temp/profile to a data volume, bound Gradle workers, and stop only the owned export tree on timeout. |
| P1 | Smoke test repeated an already-fixed group bug, tested a rotated knob along the wrong axis, and returned success on failure. | Correct geometry/discovery assertions, fail with nonzero status, and add external XRSim acceptance plus control/reach regressions. |

## Reach evidence

Design reference: cockpit design eye with left/right shoulder offsets of ±18cm
horizontally, −15cm vertically and +5cm rearward. Measure the closer reference
shoulder to each physical control in the real procedural cockpit. This is a
design comparison, not a guarantee about individual anatomy or comfort.

| Control | Baseline | Revised |
|---|---:|---:|
| Tillers, rest position | approximately 75cm | 43cm |
| Rocket-cover target | initial audited target 69cm | 54cm |
| IR activation | approximately 66cm | 49cm |
| Horn | approximately 105cm | 55cm |
| Reload lever, maximum full driver-seat traverse | 83cm | 45cm |

Approximate baseline figures are analytic comparisons with the original mount
positions. Logged before/after geometry verifies the reload change and revised
positions. Test full lever travel, different seated heights, and physical
controller collisions with wearers before declaring universal comfort.

## Verification

- Godot 4.7.stable.official.5b4e0cb0f, Mobile renderer.
- **25 XRSim/OpenXR acceptance checks passed** through our xrsim Meta backend
  modules and Meta XR Operator. Verify a focused Tank Commander VR session and
  Touch Plus profile before driving it.
- Sequence: real menu click, physical engine startup, gear selection, tiller grab/
  release, grip thresholds, accidental-fire guard, turret firing without throttle,
  relocated reload, wrist-twist knob, IR toggling, and pause/resume while holding.
  Assertions read actual game state, rather than only Operator success.
- Thermal scheduling: **70 refresh requests over 167 physics ticks**, consistent
  with the 30Hz cap at 72Hz physics.
- Production cockpit smoke: **14/14 passed**.
- Gameplay state/wave/restart regression: **21/21 passed**.
- Control-dispatch regression: **15/15 passed**.
- Skill validation: five canonical skills and five matching Claude entries passed.
- Front/downward cockpit mirror captures reviewed for text, instruments, physical
  controls, and one controller representation.
- Test shutdown still reports resource/ObjectDB cleanup warnings, also present in
  the baseline harness. These warnings are not counted as gameplay passes.

No physical Quest was connected. Desktop XRSim FPS and mirror draw counts are
**not standalone Quest frame times**. The simshot mode adds a world render and
synchronous image readback; its periodic stalls are not production frame pacing.
Optical hand tracking was not proven by controller acceptance.

## Biggest next improvements

1. **Graphics/recognition:** strengthen enemy silhouettes and friend/foe recognition
   at combat distances; improve cockpit material contrast and daylight/night
   readability with stereo captures. Favor inexpensive material/geometry work.
2. **Quest performance:** native Quest 3S/3 thermal, glow and shadow A/B captures
   after warmup, including city/night/disaster scenes. Check sustained 72Hz,
   CPU/GPU frame times, dropped frames and thermal behavior. Preserve VRS_XR,
   dynamic foveation and subsampled images.
3. **World rendering:** trees/rocks already use MultiMesh and have shadows off,
   but whole-level batches cannot spatially cull individual instances. Try
   spatial chunks/LOD while preserving destructible-instance references, then
   measure on Quest before changing defaults.
4. **Pacing:** observe new players' time-to-first-drive/hit and failed startup/
   reload attempts; tune early waves from evidence.
5. **Near-field comfort:** validate full control travel with both hands,
   controllers and optical hands, varied seated heights and maximum turret angles.

## Reproduce

Run scenes/xr_interaction_smoke.tscn, scenes/gameplay_qa.tscn,
scenes/control_regression.tscn and scenes/reach_audit.tscn with isolated Godot
user data so saved tuning/autostart cannot change the scenario.

Launch scenes/xr_audit.tscn under Meta XR Simulator + Operator, with user arguments
--xr-audit --simshot after the required -- separator. Then execute:

~~~
node tools/xrsim_audit.mjs <xrsim-repo> <isolated-Godot-user-dir> <evidence-dir>
~~~

Use tools/build_quest.py --help for APK export. Run inside the host-local build
lease with explicit engine, output, profile, editor settings and matching Android
template paths. Verify APK version/package/ABI/signature before alpha upload.
